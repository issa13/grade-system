# نظام إدارة علامات الطلاب

موقع للأستاذ لإدارة الصفوف والطلاب والمواد، وتسجيل الحصص (مشاركة، شغب، تأخير، غياب، وظائف)، وإدخال العلامات بنفس شكل كشف الإكسل (الفصل، النصف، السعي، معدل النصف، النهائي من 20)، ومشاركة العلامات مع كل طالب برابط خاص يتحدّث مباشرة.

التقنيات: Next.js (موقع ثابت) + Supabase (قاعدة بيانات وتسجيل دخول) + Tailwind، والنشر على GitHub Pages. كلها مجانية.

---

## التشغيل لأول مرة (حوالي 15 دقيقة)

### 1) إنشاء قاعدة البيانات على Supabase (مجاني)
1. ادخل إلى https://supabase.com وأنشئ حساباً، ثم **New project**.
2. بعد إنشاء المشروع افتح **SQL Editor ← New query**، والصق كل محتوى الملف `supabase/schema.sql`، ثم اضغط **Run**.
3. افتح **Project Settings ← API** وانسخ:
   - `Project URL`
   - `anon public key`

### 2) التشغيل على جهازك (للتجربة)
1. ثبّت آخر نسخة من **Node.js** من https://nodejs.org
2. داخل مجلد المشروع، انسخ الملف `.env.example` إلى ملف جديد اسمه `.env.local` وضع فيه القيمتين:
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=المفتاح
   ```
3. افتح Terminal داخل المجلد وشغّل:
   ```
   npm install
   npm run dev
   ```
4. افتح http://localhost:3000 ← **حساب جديد** ← أدخل بريدك وكلمة مرور ← أكّد البريد من الرسالة ← سجّل الدخول.

> **مهم للأمان:** بعد إنشاء حسابك، من Supabase افتح **Authentication ← Sign In / Providers** وأوقف **Allow new users to sign up** حتى لا يستطيع أحد غيرك إنشاء حساب.

### 3) النشر على الإنترنت عبر GitHub Pages (مجاني، بدون Vercel)
الموقع مبني كموقع ثابت (Static)، لذلك يكفي GitHub وحده. الملف `.github/workflows/deploy.yml` يبني الموقع وينشره تلقائياً.

1. أنشئ مستودعاً جديداً على **GitHub** (مثلاً `grade-system`). اجعله **Public**، لأن GitHub Pages المجاني يتطلب مستودعاً عاماً. لا توجد أسرار في الكود: ملف `.env.local` لا يُرفع، ومفتاح `anon` مصمَّم ليكون علنياً، والبيانات محمية بـ RLS.
2. ارفع المجلد إلى الفرع `main`.
3. في المستودع: **Settings ← Pages ← Build and deployment ← Source** واختر **GitHub Actions**.
4. في المستودع: **Settings ← Secrets and variables ← Actions ← تبويب Variables ← New repository variable** وأضف:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
5. افتح تبويب **Actions** ← **Deploy to GitHub Pages** ← **Run workflow** (أو اعمل أي push). بعد دقيقتين يصبح الموقع على:
   `https://اسم-المستخدم.github.io/grade-system/`
6. في Supabase افتح **Authentication ← URL Configuration**:
   - **Site URL**: رابط موقعك أعلاه
   - **Redirect URLs**: أضف `https://اسم-المستخدم.github.io/grade-system/**`
   (حتى تعمل رسائل تأكيد البريد وتغيير كلمة المرور).

كل `git push` إلى `main` ينشر التحديث تلقائياً.

> ملاحظة: مشاريع Supabase المجانية تتوقف مؤقتاً إذا لم تُستعمل لمدة أسبوع. مهمة **Keepalive** (أدناه) تمنع ذلك، وإذا توقف المشروع رغم ذلك يكفي فتح لوحة Supabase والضغط على **Restore**.

## التحديث إلى الإصدار 2

1. **قاعدة البيانات (مرة واحدة):** Supabase ← **SQL Editor ← New query**، الصق محتوى `supabase/migrations/002_v2.sql` واضغط **Run**. لا يمس البيانات الموجودة، وآمن لإعادة التشغيل.
2. **ارفع الملفات إلى GitHub** (الفرع `main`)، بما فيها مجلد `.github/workflows` — يُنشر الموقع تلقائياً.
3. **النسخة الاحتياطية الأسبوعية بالإيميل:** في المستودع **Settings ← Secrets and variables ← Actions ← تبويب Secrets ← New repository secret** وأضف:
   | الاسم | القيمة |
   |---|---|
   | `SUPABASE_SERVICE_ROLE_KEY` | من Supabase: **Project Settings ← API ← service_role** (لا تضعه في أي مكان آخر) |
   | `SMTP_USER` | بريد Gmail الذي يُرسل النسخة |
   | `SMTP_PASS` | «كلمة مرور تطبيق» من Google: https://myaccount.google.com/apppasswords (تحتاج التحقق بخطوتين) |
   | `BACKUP_TO` | البريد الذي تصله النسخة |

   ثم جرّبها: **Actions ← Weekly backup ← Run workflow**. يصل الإيميل خلال دقائق. إذا فشلت، GitHub يرسل لك إيميلاً تلقائياً.
4. **Keepalive:** لا يحتاج أسراراً جديدة (يستعمل نفس المتغيرين `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`). جرّبه مرة: **Actions ← Keepalive ← Run workflow**، ثم تأكد في الموقع: **الإعدادات ← البيانات ← «آخر نبضة»**.

## الإشعارات على التلفون (التحديث 4)

التنبيهات المهمة تصل إلى تلفونك حتى لو كان الموقع مسكّراً. بدون خادم: مهمة على GitHub تعمل كل ساعة، تحسب التنبيهات بنفس محرك الموقع، وترسل الجديدة منها فقط.

**الإعداد (مرة واحدة):**
1. Supabase ← **SQL Editor**: شغّل `supabase/migrations/004_push.sql`.
2. على جهازك داخل مجلد المشروع: `npm install` ثم `npm run vapid`. يطبع مفتاحين: **Public Key** و **Private Key**.
3. في المستودع على GitHub ← **Settings ← Secrets and variables ← Actions**:
   - تبويب **Variables**: `NEXT_PUBLIC_VAPID_PUBLIC_KEY` = المفتاح العام.
   - تبويب **Secrets**: `VAPID_PRIVATE_KEY` = المفتاح الخاص. (لا تضعه في أي ملف ولا في الموقع.)
   - `SUPABASE_SERVICE_ROLE_KEY` موجود من النسخة الاحتياطية.
4. ارفع التحديث (push إلى main) حتى يُبنى الموقع بالمفتاح العام.
5. على كل جهاز: الموقع ← **الإعدادات ← الإشعارات ← «🔔 تفعيل الإشعارات على هذا الجهاز»**.
   - **أندرويد:** من Chrome مباشرة.
   - **آيفون (iOS 16.4+):** أولاً Safari ← مشاركة ← «إضافة إلى الشاشة الرئيسية»، ثم افتح التطبيق من الأيقونة وفعّل من داخله.
6. تجربة: GitHub ← **Actions ← Push notifications ← Run workflow ← test**. يصل «تجربة ✓» إلى كل الأجهزة خلال دقيقة.

**كيف يعمل:** اختر التنبيهات التي تصل كإشعار (الافتراضي: غياب متتالٍ، حصص غير مسجلة، نسبة حضور منخفضة، هبوط مفاجئ) وساعات الهدوء (20:00–07:00) والعطلة الأسبوعية من الإعدادات ← الإشعارات. التنبيهات المتشابهة تُجمع في إشعار واحد، ونفس التنبيه لا يصل مرتين إلا إذا تغيّرت حالته. الضغط على الإشعار يفتح الطالب أو الحصة مباشرة. ملاحظة: GitHub قد يؤخّر المهام المجدولة بضع دقائق.

## التحديث 3 (إحصائيات الطالب، تحميل PDF، حماية البيانات)

1. Supabase ← **SQL Editor**: شغّل `supabase/migrations/003_student_stats.sql` مرة واحدة (بعد 002). إذا نسيت، يظهر في الموقع شريط أحمر يقول أي ملف تشغّل.
2. **تحميل PDF** في كل صفحة إحصائيات (الطالب، المادة، الصف، إحصائياتي): زر «⤓ تحميل PDF» ← في نافذة الطباعة اختر «حفظ بصيغة PDF». الملف هو نفس الصفحة بنفس الأرقام والإعدادات.
3. **رابط الطالب** يعرض الآن نفس إحصائيات صفحة الطالب عند الأستاذ. ما يظهر يُختار من **الإعدادات ← ما يراه الطالب** (كل قسم وحده). «الترتيب» و«معدل الصف» متوقفان افتراضياً: لحسابهما تُرسل علامات الزملاء بدون أسماء وبترتيب عشوائي.
4. **بحث سريع عن طالب:** Ctrl+K أو / (أو أيقونة البحث).
5. **سجل الأخطاء:** الإعدادات ← البيانات. إذا حدثت مشكلة، انسخه وأرسله.

## ميزات الإصدار 2

- **البرنامج الأسبوعي** (الصفحة الرئيسية): أيام × ساعات من مواعيد المواد، عمود اليوم مميّز، الحصة الجارية بإطار «الآن» وزر «سجّل»، والحصص التي مضى وقتها بدون تسجيل بالبرتقالي. ضغطة على حصة تفتح تسجيلها مباشرة (تُنشأ تلقائياً بدون تكرار). 📊 (أو ضغطة مطوّلة على التلفون) يفتح إحصائيات الحصة. على التلفون: يوم واحد مع شريط الأيام والسحب بينها. قائمة الصفوف أصبحت في «الصفوف»، ويمكن إرجاعها كصفحة رئيسية من الإعدادات ← البرنامج الأسبوعي.
- **العمل بدون إنترنت:** تسجيل الحصة، كشف العلامات، وحالة الواجبات تُحفظ على الجهاز وتُرسل وحدها عند عودة الشبكة (المؤشر: «✓ محفوظ» / «بدون إنترنت — 3 تغييرات بانتظار الإرسال»). بين جهازين يربح التعديل الأحدث، والتعديل الأقدم المرفوض يظهر في «تعديلات لم تُطبّق».
- **تطبيق على الشاشة الرئيسية (PWA):** أندرويد: زر «تثبيت». آيفون: Safari ← مشاركة ← «إضافة إلى الشاشة الرئيسية». عند نشر نسخة جديدة تظهر «تحديث جديد — اضغط للتحميل». صفحة الطالب لا تُحفظ على الجهاز.
- **رسائل واتساب للطالب:** «إدخال الأرقام» في صفحة الصف (أو يرسل الطالب رقمه من صفحة علاماته للموافقة)، ثم «رسائل الصف» أو زر واتساب لكل طالب. القالب والفترة من الإعدادات ← واتساب.
- **تقرير PDF:** صفحة الصف ← «تقارير PDF»: صفحة A4 لكل طالب مع الشعار والتوقيع (الإعدادات ← الملف الشخصي) وملاحظة الأستاذ. «طباعة / حفظ PDF».
- **التنبيهات:** الجرس 🔔 في أعلى الموقع وشريط أهم 3 تنبيهات فوق البرنامج. «تمّ» أو «ذكّرني بعد أسبوع». كل قاعدة ورقم من الإعدادات ← التنبيهات.
- **مسار الطالب:** رسم في صفحة الطالب (لكل مادة أو كل المواد) مع معدل الصف والهبوط المفاجئ بالأحمر، وسهم ↑ ↓ → بجانب الاسم. تاريخ كل امتحان يُضاف من رأس العمود في كشف العلامات (اختياري).
- **مقارنة النصفين:** في صفحة الطالب وإحصائيات المادة والصف وإحصائياتي، وورقة «مقارنة النصفين» في ملف Excel. تظهر بعد أول علامة من النصف الثاني.
- **نسخة احتياطية أسبوعية بالإيميل** (كل أحد صباحاً) و**منع توقف Supabase** (نبضة كل يومين، و commit شهري على الفرع `keepalive` لا يعيد نشر الموقع).

## طريقة الاستعمال

1. **الصفوف:** أنشئ صفاً (مثلاً BT3 - كهرباء صناعية).
2. **الطلاب:** أضف الطلاب يدوياً، أو «لصق أسماء» (اسم في كل سطر)، أو «استيراد Excel». يمكن رفع ملف كشف العلامات `.xlsm` مباشرة، فيتعرّف على عمود «الاسم» تلقائياً، مع معاينة وكشف الأسماء المكررة.
3. **المواد:** أضف المواد لكل صف، ولكل مادة وزن في المعدل العام.
4. **الحصص:** داخل المادة ← «موعد» لكل حصة أسبوعية (مثلاً الإثنين 8:00) ← «توليد الحصص» للفصل الأول أو الثاني. تُستثنى العطلة الأسبوعية والعطل المحددة في الإعدادات.
5. **تسجيل الحصة:** افتح الحصة واضغط على الأزرار لكل طالب. الحفظ تلقائي. اختصارات لوحة المفاتيح: ↑↓ اختيار الطالب، 1 مشاركة، 2 شغب، 3 تأخير، 4 غياب، 5 وظيفة، N ملاحظة، Ctrl+Z تراجع.
6. **كشف العلامات:** الفصل 1-4، النصف 1-2، السعي، معدل النصف، النهائي. سطر العناوين وعمود الاسم يبقيان ثابتين عند التمرير. اكتب العلامة واضغط Enter للانتقال للطالب التالي. اكتب «م» للمعفى. النصف والنهائي يُحسبان فوراً.
7. **رابط الطالب:** في قائمة الطلاب ← «نسخ» وأرسله للطالب. يرى علاماته فقط وتتحدّث الصفحة مباشرة عند تعديلك. يمكن «تجديد» الرابط (يتوقف القديم) أو «تعطيله». زر «طباعة / PDF» في صفحة الطالب.
8. **التصدير:** ملخص العلامات ← «تصدير Excel» يعطي ملفاً فيه ورقة لكل مادة بشكل الكشف + ورقة ملخص. ويمكن تصدير سجل الحصص والواجبات وقائمة الطلاب.

## الإحصائيات
- **إحصائياتي** (في القائمة): ملخص كل الصفوف، الحصص التي تحتاج تسجيل، الطلاب الذين يحتاجون متابعة، وأفضل الطلاب.
- **إحصائيات الصف** و**إحصائيات المادة** (تبويب «الإحصائيات»): المعدلات، نسبة النجاح، توزيع التقديرات، الحضور، الترتيب.
- **صفحة الطالب**: اضغط على اسم أي طالب لرؤية معدله وترتيبه وحضوره وسلوكه في كل مادة.
- قبل اكتمال كل العلامات تُستعمل «العلامة حتى الآن» (نفس المعادلة بالعلامات الموجودة فقط).
- **ترتيب الطلاب**: صفحة الصف ← الطلاب: اسحب من ⠿ أو استعمل ▲▼، أو «ترتيب أبجدي».
- زر ⓘ بجانب أغلب العناوين والخانات يشرح ماذا تفعل.

## التقديرات الافتراضية
ممتاز ≥ 18 · جيد جداً ≥ 16 · جيد ≥ 14 · مقبول ≥ 10 · راسب < 10 (قابلة للتعديل).

## المعادلات (قابلة للتعديل من الإعدادات ← حساب العلامات)

- كل العلامات من 20 افتراضياً (الفصل، النصف، السعي)، وكل علامة تُصدَّر محوّلة إلى 20.
- **معدل النصف** = (معدل الفصلين × 15 + النصف × 25) ÷ 40
- **النهائي** = معدل النصف 1 × 0.4 + معدل النصف 2 × 0.4 + السعي 1 × 0.1 + السعي 2 × 0.1
- لا توجد علامات ← فارغ. توجد علامة ناقصة ← **NC** (أو صفر حسب الإعداد).
- **السعي** محسوب افتراضياً من السلوك والوظائف: العلامة الأساسية + نقاط المشاركة والشغب والتأخير والغياب والوظائف (كل النقاط قابلة للتعديل). يمكن إدخاله يدوياً، والقيمة اليدوية تتقدّم على المحسوبة.
- **عند تغيير حساب العلامات أو نقاط السلوك** يسألك الموقع: تطبيق التغيير على النصف الحالي فقط (النصف الآخر يبقى بإعداداته السابقة)، أو على السنة كلها، أو إلغاء.
- **أوزان خاصة بمادة:** من كشف العلامات ← «أوزان المادة»، تغيّر الأوزان لهذه المادة فقط.

## الأمان والتراجع
- كل جدول محمي بـ RLS: لا يرى أي حساب إلا بياناته. رابط الطالب يعرض بيانات ذلك الطالب فقط، وتُخفى العلامات غير المنشورة (الإعدادات ← ما يراه الطالب).
- الحذف يذهب إلى **سلة المحذوفات** ويمكن استعادته.
- **سجل التعديلات** يحفظ كل تغيير (قبل/بعد/الوقت) مع زر «استرجاع».

## للمطوّرين
- `npm test` — اختبارات محرك حساب العلامات (`src/lib/grades.test.ts`)
- `npm run build` — بناء الموقع الثابت في المجلد `out/`
- مخطط قاعدة البيانات: `supabase/schema.sql` ثم `supabase/migrations/002_v2.sql` ثم `003_student_stats.sql` ثم `004_push.sql` (كلها آمنة لإعادة التشغيل). عند إضافة ملف جديد: ارفع `app_schema_version()` و `REQUIRED_SCHEMA` في `src/components/schema-check.tsx`.
- `npm run push -- --dry-run` — حساب الإشعارات بدون إرسال · `npm run vapid` — إنشاء مفتاحَي الإشعارات
- `npm run backup -- --dry-run` — تجربة النسخة الاحتياطية على جهازك بدون إرسال (يحتاج `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY`)
- `public/sw.js` — رقم النسخة يُكتب تلقائياً بعد البناء (`scripts/sw-version.mjs`)
